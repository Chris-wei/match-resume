# AI 简历分析小程序 · 个人版设计文档

> 设计蓝本：[resume-matcher](https://provecv.com) 的「LLM 找证据 + 代码校验引用 + 确定性打分」思路，
> 但砍到**一个人、一个周末出 MVP、先验证付费**的最小形态。
>
> **一句话定位**：粘贴简历 + 粘贴 JD，30 秒拿到一份「每条判断都能戳回原文」的匹配报告，
> 并直接给你改好的简历句子。免费看评分和 1 条致命问题，9.9 元解锁完整报告。

---

## 0. 为什么这样设计（先讲取舍，再看细节）

| resume-matcher 原版 | 个人小程序版的对策 | 为什么 |
|---|---|---|
| 支持 PDF / 双栏 / 扫描件 / docx | **MVP 只做纯文本粘贴** | 原项目自己都承认双栏拼错行、扫描件报错、docx 没做。这三坑能吃掉你一个月，且解析一崩用户直接走人 |
| 海外+国内两套模型链、多地部署、failover | **一家模型 + 一个地域** | 个人阶段没必要，先把付费跑通 |
| Sentry / 告警邮件 / 全站限流 / 加盐哈希 IP | **微信云开发内置限流 + 云函数日志** | 够用，别自己运维 |
| Pro 订阅、追问重分析、200 次额度 | **免费 1 次 + 9.9 元单次解锁** | 简历是低频急用需求，单次付费比订阅好卖 |
| TODO 里才接付费 | **付费是第一版就有的闭环** | 先验证有没有人掏钱，再谈功能 |

**保留不变的三条灵魂**（这是你区别于"ChatGPT 套壳"的唯一壁垒）：

1. LLM 每条判断**必须给出原文引用片段**
2. **代码逐字校验**引用是否真的在简历/JD 里，找不到就降级标灰，绝不让模型圆谎
3. **打分由代码算**，同一份输入永远同一个分，不受模型随机性影响

## 1. 产品形态

### 1.1 用户路径（5 步，目标 60 秒走完）

```
首页(说清价值) → 粘贴简历+JD → 30秒分析动画 → 报告页 → 付费解锁完整版
                     │                          │
                     └─ 文本校验失败则拦截提示 ───┘
```

| 页面 | 内容 |
|---|---|
| `/pages/index/index` | 一句话 + 示例报告动图 + 「免费试一次」按钮 |
| `/pages/analyze/analyze` | 两个文本框（简历 / JD）、字数提示、开始按钮 |
| `/pages/report/report` | 匹配分 + 雷达图 + 证据列表 + 改写建议 + 付费按钮 |
| `/pages/pay-success/pay-success` | 解锁成功，展示完整报告 |
| `/pages/legal/legal` | 隐私政策 + 用户协议（合并一个入口） |

### 1.2 免费 vs 付费

| 能力 | 免费 | 9.9 元单次解锁 |
|---|---|---|
| 综合匹配分（0-100） | ✅ | ✅ |
| 雷达图（5 维度） | ✅ | ✅ |
| 致命问题 | 只看 **1 条** | 全部问题 |
| 每条判断的原文证据 | 只看 1 条 | 全部 |
| 逐条改写建议（可直接复制） | ❌ | ✅ |
| 缺失项 → 该补什么 | ❌ 只给提示 | ✅ 具体话术 |
| 保存报告 30 天 | ❌ | ✅ |

> **关键体验**：免费报告必须"够好到心动，又不够用"。用户看到那条致命问题被说中要害，
> 又看到下面灰着的"还有 7 条问题 + 改写建议"，9.9 元的转化点就成立了。
> 别免费给太多，也别免费版烂到没价值。

## 2. 核心流水线（照搬原项目的分层思想，压成 5 步）

```
用户输入(文本)
   │  ① 前端校验 + 脱敏
   ▼
[云端] ② 切分简历 → S1..Sn 片段        ← 代码
   │     ③ JD 拆原子要求 + 每条带 jd_quote   ← LLM，代码校验 quote 存在
   ▼
   │     ④ 证据检索：技能别名 + 关键词重叠     ← 代码（不用向量库）
   ▼
   │     ⑤ 逐条判定：命中/缺失/模糊 + 引用片段  ← LLM
   ▼
   │     ⑥ 引用校验：逐字对原文，失败→unclear   ← 代码（壁垒在这里）
   ▼
   │     ⑦ 确定性打分 + 雷达 + 改写建议        ← 代码打分，LLM 只写改写
   ▼
报告 JSON → 前端渲染
```

### 各步骤职责表

| 步骤 | 谁做 | 输入 | 输出 | 失败怎么办 |
|---|---|---|---|---|
| ① 校验脱敏 | 小程序端 JS | 两段文本 | 脱敏后文本 + 本地字数统计 | 邮箱/手机正则告警，超长截断提示 |
| ② 切分 | 云函数（代码） | 简历文本 | `S1..Sn` 片段数组 | 按空行/换行切，容错 |
| ③ JD 拆解 | LLM（JSON 模式） | JD 文本 | `[{req, jd_quote, category, weight}]` | zod 校验失败重试 2 次，仍失败则该 JD 要求标 `unclear` |
| ④ 检索 | 云函数（代码） | 片段 + 要求 | 每个要求的候选证据片段 ID 列表 | 返回空也继续，判为缺失 |
| ⑤ 判定 | LLM | 要求 + 候选证据 | `{verdict, quote_id, reason}` | 重试 2 次 |
| ⑥ 引用校验 | **纯代码** | 判定结果 + 原文 | 校验通过 / 降级 `unclear` | 不匹配直接降级，不回退给 LLM |
| ⑦ 打分+改写 | 代码打分 / LLM 改写 | 校验后判定 | score、雷达、rewrite 数组 | 打分必成功；改写失败不影响主报告 |

### 为什么第 ⑥ 步是你的护城河

免费 ChatGPT 会给这样的回答：

> "你具备扎实的分布式经验，建议补充具体 QPS 数据。"

——可用户简历里压根没写分布式。这就是幻觉，用户一眼不信。

你的第 ⑥ 步会把它抓出来：模型引用的句子在原文里找不到 → 整条降级成「无法确认」，前端灰显并标注"此项需你自行核对"。
剩下的每一条都能戳回简历原句。**信任就这么建立的。**

## 3. 数据契约（LLM 输入输出 + 打分）

### 3.1 LLM 阶段一：JD 拆解（要求结构化输出）

```json
{
  "requirements": [
    {
      "id": "R1",
      "text": "3年以上 Java 后端开发经验",
      "jd_quote": "3-5年 Java 后端开发经验",
      "category": "experience",
      "weight": 1.0
    }
  ]
}
```

> `jd_quote` **必须逐字出现在 JD 原文中**。代码拿到后做一次 `jd.includes(quote)`，
> 不存在直接拒收这条，让 LLM 重来。

### 3.2 LLM 阶段二：逐条判定

```json
{
  "req_id": "R1",
  "verdict": "hit" | "partial" | "miss" | "unclear",
  "quote": "负责后端服务开发，使用 Java / Spring Boot",
  "quote_id": "S12",
  "years_hint": 2,
  "reason": "简历显示 Java 后端经验，但未给出年限，按上下文估算约 2 年"
}
```

### 3.3 引用校验（纯代码，伪代码）

```ts
function verify(evidence: Judgment, resume: string, jd: string): Judgment {
  const src = evidence.quote_id.startsWith('S') ? resume : jd
  const found = src.includes(evidence.quote)
  if (!found) {
    return { ...evidence, verdict: 'unclear', reason: '引用的原文未找到，请自行核对' }
  }
  return evidence
}
```

可选增强：允许 ±2 字符的标点/空格差异，避免模型改写标点导致误杀。

### 3.4 打分（确定性代码，同一输入必得同分）

```ts
const CATEGORIES = ['skills', 'experience', 'projects', 'education', 'keywords'] as const

// 每个 requirement 给出 0~1 的命中度
function hitScore(v: Verdict, yearsHint?: number, reqYears?: number): number {
  if (v === 'miss') return 0
  if (v === 'unclear') return 0.15     // 不明确给一点点，不白给
  if (v === 'partial') return 0.55
  if (v === 'hit') {
    if (!reqYears) return 1
    return Math.min(1, (yearsHint ?? 0) / reqYears)  // 年限不足按比例打折
  }
  return 0
}

// 加权总分 + 硬门槛封顶
let total = 0, weightSum = 0
for (const r of requirements) {
  total += hitScore(r.verdict, r.yearsHint, r.reqYears) * r.weight
  weightSum += r.weight
}
let score = Math.round((total / weightSum) * 100)

// 硬门槛：JD 明确要求"5年+"，简历完全没提 → 最高封顶 60
if (hasHardGate && totalHits === 0) score = Math.min(score, HARD_GATE_CAP)
```

雷达图按 `category` 分组算平均分。**所有参数（`weight`、`HARD_GATE_CAP`）集中在 `score.config.ts` 顶部**，方便你调手感。

## 4. 隐私 & 合规（照搬原项目最值得抄的部分）

这是简历工具的生死线，别省。

| 措施 | 实现 |
|---|---|
| **发模型前脱敏** | 小程序端就用正则把邮箱、手机号、身份证号替换成 `[EMAIL]`/`[PHONE]`/`[ID]`，模型永远看不到真实值 |
| **不存原文** | 云数据库只存：报告 JSON（已脱敏）+ 分数 + 创建时间。**简历原文不落库** |
| **报告自动过期** | 付费报告 30 天后云函数定时清理（个人版比原项目 90 天更短，降低风险） |
| **一键删除** | 「删除这份报告」即时删除，微信侧也提供注销入口 |
| **计数与身份分离** | 用 `wx.login` 的 openid 做用户标识，免费次数绑 openid，**删了小程序重进也不重置**（微信机制天然保证） |
| **类目选择** | 个人主体走 **工具 / 文本处理（写作辅助）** 类目，**不要**碰"招聘""人力资源""职业中介"等需资质类目 |
| **法律文案** | 隐私政策 + 用户协议放在小程序内，明确"数据仅用于本次分析、不训练、不共享、30 天删除"。**收费前请律师过一遍**，开发期页面顶部挂「草案」水印 |

> ⚠️ 模型选型加一条硬约束：**只用承诺"不拿请求数据训练"的模型**（如支持零数据保留的厂商）。
> 原项目特意避开 DeepSeek 官方 API 就是这个原因——简历是敏感个人信息，别赌。

## 6. 防滥用（个人版够用即可）

| 规则 | 实现 |
|---|---|
| 同一 openid 免费 1 次 | 云数据库查该 openid 是否有免费报告 |
| 分析接口频率 | 云函数内置：同 openid 10 分钟内最多 3 次（防脚本刷） |
| 输入长度上限 | 简历 4000 字 / JD 2000 字，超了截断并提示 |
| 失败不扣次数 | 模型调用异常 → 不扣额度，提示重试 |
| 小程序自带安全 | 开启微信云开发的[内容安全](https://developers.weixin.qq.com/miniprogram/dev/api-backend/open-api/sec-check/) 检查违规文本 |

> 原项目那套 IP 加盐哈希、全站每日上限、Turnstile 人机验证，个人 MVP **先不做**。
> 等真有人来刷你再说——大概率前期根本没那个流量。

## 7. 付费设计（第一天就上）

### 为什么是单次 9.9，不是会员

简历分析是**低频 + 急用**：用户求职那两周用一次，入职后流失。
会员订阅的复购率会很难看，而"我明天要投简历，现在就要改"的 9.9 元几乎不用犹豫。

### 支付流程

```
报告页点「解锁完整报告 9.9元」
   → 云函数 createOrder：生成订单 + 预支付参数
   → 微信支付（小程序 wx.requestPayment，个人主体可用「虚拟支付」或交易组件，需确认类目资质）
   → 支付回调云函数：把报告 isPaid=true
   → 前端跳转 pay-success，渲染完整版
```

### 两个必须提前确认的点（别踩坑）

1. **个人主体的支付能力**：微信小程序个人主体开通支付/虚拟支付有类目限制。
   **动手前先去微信公众平台查清楚你的「工具类目」能不能开支付**，
   不能开就要么换企业主体（个体户营业执照很便宜），要么先走"免费 + 广告"验证需求。
2. **收入申报**：9.9 元也是经营/劳务收入，跑起来后记得申报，别装不知道。

## 8. 成本测算（心里有数才敢上线）

假设：**日活 50 人，其中 15% 付费 = 每天约 7.5 单**

| 项目 | 单价 | 日成本（50 次分析） |
|---|---|---|
| 大模型（Flash 级，约 2K 输入 + 1K 输出 token/次） | ≈ ¥0.01-0.03 / 次 | ¥0.5-1.5 |
| 微信云开发（数据库+云函数+存储） | 基础档内有免费额度 | ≈ 0（前期） |
| 微信支付手续费 | 0.6% × 9.9 | 日流水 ¥74 × 0.6% ≈ ¥0.45 |

**日毛利 ≈ ¥74 - ¥2 ≈ ¥72，月约 ¥2000+**（这是 50 日活的乐观估算，别当承诺）。

> 结论：模型成本几乎可以忽略，**真正贵的是获客**。所以别在 MVP 里堆模型链和运维，
> 把时间砸在小红书/朋友圈发"前后对比"内容上。

## 9. 上线节奏（90 天，别拖）

| 时间 | 做什么 | 成功标准 |
|---|---|---|
| **第 1 周** | 不开小程序，做"人工版"：让用户粘贴文本，你手动跑 prompt 出报告，截图问"值 9.9 吗" | 10 个人里 ≥3 个愿意付 |

## 附录 A：MVP Prompt 骨架（可直接用）

**`prompts/jd-split.txt`**

```
你是简历筛选专家。把下面这段「职位描述」拆成原子要求。
每条要求必须：
1. text：一句话描述这个要求
2. jd_quote：从原文【逐字复制】能证明这条存在的句子，一字不改
3. category：skills | experience | projects | education | keywords
4. weight：0.5~1.5，越关键越大
5. 若含年限（如"3年以上"），提取 years 数字

只输出 JSON，格式：{ "requirements": [{ "id":"R1", ... }] }
不要输出任何解释。
```

**`prompts/judge.txt`**

```
你是严格的简历评审。判断候选人的简历是否满足下面的某条 JD 要求。
规则：
- verdict：hit（明确满足）/ partial（沾边但不充分）/ miss（没有）/ unclear（简历信息不足，不能下结论）
- quote：从简历原文【逐字复制】支持你判断的句子；如果 verdict 是 miss 或 unclear，quote 留空字符串
- reason：一句话解释，中文，口语化
- 若涉及年限，给 years_hint（数字，不知道就省略）

严禁编造简历里没有的内容。找不到原文支撑就判 unclear，不要硬凑。
只输出 JSON：{ "req_id":"R1", "verdict":"...", "quote":"...", "reason":"..." }
```

> 注意两个 prompt 里都强制 `quote 留空` 当 miss/unclear —— 这样代码校验时
> 空 quote 直接跳过，不会出现"模型给了一句不存在的话"被你误判成命中。

## 附录 C：PDF 上传优先方案（替代纯粘贴）

> **为什么要改**：纯文本粘贴抬高操作门槛，用户手边有 PDF 却要自己复制，流失在第一步。
> **为什么不直接做完整解析**：双栏错行、扫描件 OCR、加密 PDF 是深坑（resume-matcher 自己都没做完，见其 TODO）。
> **折中**：上传优先、解析兜底。大多数用户走顺畅的上传路径，只有踩到坑的人才降级手动确认。

### C.1 用户路径（一个主路径 + 一个兜底）

```
上传页
 ├─ 点「选择简历 PDF」→ 上传到云存储 → 云函数提取文本
 │     ├─ 提取成功且字数正常 → 回填到文本框，用户可编辑确认 → 继续分析
 │     ├─ 文本过少(<100字)    → 判定为扫描件 → 提示"请粘贴文本"并聚焦输入框
 │     ├─ 加密/损坏/抛错      → 提示"暂不支持该文件，请粘贴文本"
 │     └─ 双栏疑似错序        → 仍展示结果，顶部黄条提示"版式可能错乱，可手动调整"
 └─ 或点「直接粘贴文本」      → 走纯文本路径（永远可用）
```

**关键体验**：解析结果**一定展示给用户确认**，不让黑盒直接喂给模型。乱了能当场改，比事后拿到乱码报告强十倍。

### C.2 解析兜底判定表

| 情况 | 识别信号 | 动作 |
|---|---|---|
| 正常文本框 PDF | 提取文本 ≥ 100 字，行数合理 | 回填 + 用户确认 |
| 扫描件（无文字层） | 提取文本 < 100 字或全空 | 提示粘贴，不上报错误 |
| 加密/损坏 | pdfjs 抛错 | 提示"暂不支持该文件" |
| 双栏疑似错序 | 单行内出现明显语义跳跃（可选启发式） | 黄条提醒可手动改，不阻断 |
| 文件过大 | 超过 5MB | 上传前拦截，提示压缩 |

### C.3 云函数解析骨架

```typescript
// cloudfunctions/extractPdf/index.ts
import pdf from 'pdfjs-dist/legacy/build/pdf.js';

export async function extractPdf(fileID: string) {
  const buf = await downloadFromCloudStorage(fileID);      // 云存储下载
  let doc;
  try {
    doc = await pdf.getDocument({ data: buf }).promise;
  } catch {
    return { ok: false as const, reason: 'invalid', message: '文件无法解析，请粘贴简历文本' };
  }

  let text = '';
  for (let i = 1; i <= doc.numPages; i++) {
    const page = await doc.getPage(i);
    const content = await page.getTextContent();
    text += content.items.map((it: any) => it.str ?? '').join(' ') + '\n';
  }
  const cleaned = text.replace(/\s+\n/g, '\n').trim();

  if (cleaned.length < 100) {
    return { ok: false as const, reason: 'scan', message: '检测到扫描件，请粘贴简历文本' };
  }
  return { ok: true as const, text: cleaned };
}
```

前端拿到 `ok:false` 就走粘贴引导，拿到 `ok:true` 就把 `text` 填进文本框。上传前先做 `wx.chooseMessageFile` / `wx.chooseMedia` 选文件 + 大小校验。

### C.4 版本演进（解析能力随验证逐步加码）

| 版本 | 输入能力 | 工作量 | 说明 |
|---|---|---|---|
| v1 | 上传文本框 PDF + 失败降级粘贴 | 2-4 天 | 本方案，主路径已很顺 |
| v2 | 解析结果可视化高亮（哪段被当成哪栏） | 1-2 天 | 降低"错乱却不知"的焦虑 |
| v3 | 双栏分列检测（按 x 坐标聚类） | 5-7 天 | 参考 pdfjs 的 `transform` 坐标 |
| v4 | 扫描件 OCR（接云 OCR API） | 3-5 天 | 只在扫描件占比高时值得做 |
| v5 | docx 支持 | 3-5 天 | `mammoth` 之类库，Node 侧简单 |

**原则**：先验证"分析价值有人付钱"，再按真实用户踩坑比例决定 v3/v4 的优先级，别预判。
